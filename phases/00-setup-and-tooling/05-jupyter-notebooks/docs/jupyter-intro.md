# Jupyter Notebook 完全介绍

> 一个让你边写代码边看结果的交互式编程环境。Python 数据科学和 AI 研究的事实标准工具。

---

## 一、它是什么

Jupyter Notebook 是一个**通过浏览器使用的交互式编程工具**。你打开的是一个网页，但背后运行的是真实的 Python 进程。

```
浏览器界面（你看到的） ←→ Python 内核（实际跑代码的）
     前端                         后端
```

三个关键事实：

1. **它不是编辑器。** 它不是 VS Code / PyCharm 的替代品。它是另一种工作方式。
2. **它不产生 exe。** 它本质上是一个本地网站，你通过浏览器访问。
3. **文件格式是 `.ipynb`。** 和 `.py` 不兼容，但可以互相转换（`jupyter nbconvert`）。

---

## 二、.py 脚本 vs .ipynb notebook

这是理解 notebook 最关键的部分。同一个实验，两种做法：

### .py 脚本的工作方式

```
┌─────────────────────────────┐
│  train.py                   │
│                             │
│  import torch               │
│  model = CNN()              │
│  model.fit(data, epochs=10) │  ← 所有代码写在一个文件里
│  print(results)             │
│  plt.plot(losses)           │
│  plt.savefig('loss.png')    │
└─────────────────────────────┘
         │
         ▼  python train.py
┌─────────────────────────────┐
│  终端输出（文字流）           │
│  Epoch 1: loss=0.342        │
│  Epoch 2: loss=0.218        │
│  ...                        │
│  loss.png 保存到硬盘          │
└─────────────────────────────┘
```

- 从第一行跑到最后一行
- 输出进终端或保存到文件
- 想看中间结果？加 `print()`，重新跑
- 想改一个参数？改代码，重新跑**整个文件**

### .ipynb notebook 的工作方式

```
┌──────────────────┐
│ 单元格 1 (代码)   │  import torch, 定义模型
│ ► 输出            │  (无输出)
├──────────────────┤
│ 单元格 2 (代码)   │  model.fit(data, epochs=1)  ← 只跑这一步
│ ► 输出            │  loss=0.342
├──────────────────┤
│ 单元格 3 (代码)   │  plt.plot(losses)
│ ► 输出            │  [折线图直接嵌在这里]
├──────────────────┤
│ 单元格 4 (Markdown)│ ## 分析：loss 下降正常，但 epoch 5 有波动
│                   │  [纯文字，不跑代码]
└──────────────────┘
```

- 代码被拆成一个个**单元格**（cell），每一个都可以**独立运行**
- 输出直接嵌在代码下面，图表、表格、文字都在同一个页面里
- 改一个单元格 → `Shift+Enter` → **只跑这个单元格**，上面跑过的还在

**核心区别：反馈速度。** 脚本需要重跑整个文件（可能几分钟），notebook 只重跑你改的那一个单元格（几秒）。

## 三、它长什么样

打开 JupyterLab 后你会看到：

```
┌──────────────────────────────────────────────┐
│  菜单栏：File  Edit  View  Run  Kernel  ...   │
├──────────┬───────────────────────────────────┤
│ 文件浏览器 │                                   │
│          │   ┌─────────────────────────┐     │
│ 📁 code/ │   │ # 我的实验               │     │
│ 📄 a.py  │   │ 这是 Markdown 单元格      │     │
│ 📄 b.ipynb│  └─────────────────────────┘     │
│          │   ┌─────────────────────────┐     │
│          │   │ import torch            │     │
│          │   │ model = CNN()           │     │
│          │   │ [► 运行]                │     │
│          │   └─────────────────────────┘     │
│          │   ┌─────────────────────────┐     │
│          │   │ 输出结果出现在这里       │     │
│          │   │ loss=0.342              │     │
│          │   └─────────────────────────┘     │
└──────────┴───────────────────────────────────┘
```

- 左边：文件浏览器，和 VS Code 一样
- 右边：notebook 主区域，一列单元格从上到下排列
- 每个单元格左边有蓝色/绿色竖线 —— 蓝色 = 命令模式，绿色 = 编辑模式

## 四、两种单元格

### 代码单元格（Code Cell）

```python
import numpy as np
data = np.random.randn(1000)
data.mean()  # 输出自动显示在下面
```

- 写 Python 代码
- `Shift+Enter` 运行
- 最后一行表达式的值自动显示
- 可以输出图表、表格、图片

### Markdown 单元格（Markdown Cell）

```markdown
## 实验记录

这次用了 **lr=0.01**，loss 收敛到 0.05。

公式：$loss = \frac{1}{N}\sum(y - \hat{y})^2$
```

- 写笔记，不是代码
- `Shift+Enter` 渲染成格式化文档
- 支持标题、粗体、斜体、LaTeX 数学公式、表格、图片
- 用来**记录你在做什么和为什么**

## 五、Kernel（内核）—— 最重要的概念

**Kernel 是一个在后台持续运行的 Python 进程。** 所有单元格共享它。

```
单元格1 定义 a = 10      ──→  Kernel 记住了 a = 10
单元格2 定义 b = 20      ──→  Kernel 记住了 a = 10, b = 20  
单元格3 print(a + b)    ──→  Kernel 输出 30
```

三个后果：

1. **变量跨单元格持久存在。** 单元格 1 定义的 `model`，单元格 5 直接用。
2. **执行顺序由你点击决定。** 你可以先跑单元格 5，再跑单元格 2。这是便利也是陷阱。
3. **Kernel 重启后一切清空。** 所有变量、import 都没了，要从头跑。

## 六、三种魔术命令（你只需要这三个）

魔术命令以 `%` 开头，是 Jupyter 特有的，不是 Python 语法。

```python
# 1. 测量代码速度（多次运行取平均）
%timeit np.random.randn(10000)
# → 45.2 µs ± 1.3 µs per loop

# 2. 测量整段代码的耗时（只跑一次，训练用这个）
%%time
model.fit(X_train, y_train, epochs=10)
# → Wall time: 2.34 s

# 3. 让 matplotlib 图表嵌在 notebook 里（不用 plt.savefig）
%matplotlib inline
```

## 七、你可以把它当什么用

| 用途 | 说明 |
|------|------|
| **实验草稿纸** | 探索数据、试模型、调参数。改一个单元格只重跑那一步 |
| **实验记录本** | Markdown 写思路 + 代码跑结果，合在一起。过两周回来还能看懂自己在干嘛 |
| **展示报告** | 发给导师/师兄，对方不用装环境，代码图表公式全在 |
| **教学工具** | 这就是为什么这门课用 notebook——你可以逐段运行理解每一步 |

**它不是**：生产环境的部署工具、替代 VS Code 的 IDE、运行大型训练任务的平台。

## 八、和你现在的 .py 工作流怎么配合

```
                     实验阶段                     交付阶段
              ┌──────────────────┐    ┌──────────────────┐
              │  在 notebook 里    │    │  在 .py 文件里     │
              │  探索、试错、画图   │───►│  整理、封装、复用   │
              │  （草稿纸）        │    │  （定稿）          │
              └──────────────────┘    └──────────────────┘
```

具体到这门课：
1. 每节 lesson 的代码先用 `.py` 或 notebook 看一遍，理解逻辑
2. 做练习时，新建 notebook 试不同参数、画图对比
3. 写得好的工具函数，复制到 `.py` 文件存起来，以后 import 直接用

## 九、三个最重要的提醒

1. **分享前一定要 Kernel → Restart & Run All**
   - 确保从头到尾顺序执行没问题
   - 否则别人打开跑不通（因为你跳着执行了）

2. **Kernel 崩了别慌**
   - Kernel → Restart Kernel，从头再跑
   - 正常现象，不丢代码，只丢当前内存状态

3. **notebook 不适合跑通宵训练**
   - 浏览器关了、电脑休眠、网络断了，kernel 都可能挂
   - 长时间训练用 `.py` 脚本 + `nohup` 或 `tmux`
